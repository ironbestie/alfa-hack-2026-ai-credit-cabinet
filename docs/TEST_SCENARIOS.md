# Тестовые сценарии

Все сценарии работают на синтетических данных из миграций `V2`–`V4` и на моках WireMock.
Перед проверкой поднимите стек: `docker compose up --build` и дождитесь `healthy` у `app`.

Пользователи:

| Логин | Пароль | Роль |
|---|---|---|
| `client` | `password` | предприниматель |
| `manager` | `password` | сотрудник банка |

На странице `/login` пароль вводить не нужно, достаточно выбрать роль.

## Чем проверять

| Что | Команда | Что покрывает |
|---|---|---|
| Коллекция Postman | импортировать [postman/credit-cabinet.postman_collection.json](postman/credit-cabinet.postman_collection.json) и запустить папки 1 и 2 в Runner | сквозной путь клиента и ручная проверка, 30 запросов и 46 проверок |
| Та же коллекция без Postman | см. команду ниже | то же самое из терминала |
| Smoke | `powershell -ExecutionPolicy Bypass -File .\scripts\smoke.ps1` | веб, health, роли, полный сценарий API, 15 проверок |
| Прогон по всем ИНН | `bash scripts/demo-run.sh` | 13 компаний, итог и балл по каждой |
| Юнит-тесты | `./mvnw test` | скоринг, state machine, конвейер, retry и DLQ, документы |

Коллекция через newman в Docker:

```bash
docker run --rm -v "$(pwd)/docs/postman:/etc/newman" postman/newman:6-alpine \
  run credit-cabinet.postman_collection.json \
  --env-var baseUrl=http://host.docker.internal:8080 \
  --folder "1. Клиент: от подбора до выдачи" --folder "2. Ручная проверка менеджером"
```

Каждый прогон создаёт новые заявки. Чтобы вернуть базу к исходным демо-данным, выполните
`docker compose down -v` и поднимите стек заново.

## 4. Проверки надёжности и защиты

Проверено через API на запущенном стеке.

| № | Действие | Ожидаемый ответ |
|---|---|---|
| 4.1 | запрос без авторизации к `/api/applications` | `401` |
| 4.2 | клиент открывает `/api/manager/**` | `403` |
| 4.3 | повторный `POST /api/applications` с тем же `Idempotency-Key`, пока первый ещё обрабатывается | `409`, вторая заявка не создаётся |
| 4.4 | `submit` без подписанных согласий | `409`, `ILLEGAL_STATE` |
| 4.5 | сумма вне лимитов продукта | `400`, `BAD_REQUEST` с допустимым диапазоном |
| 4.6 | загрузка текстового файла с расширением `.pdf` | `400`: содержимое не совпадает с расширением |
| 4.7 | загрузка документа в заявку, где документы не запрашивали | `409` |
| 4.8 | `lookup` по ИНН, которого нет в ЕГРЮЛ | `404` |
| 4.9 | БКИ не отвечает (ИНН `7722085341`) | заявка уходит специалисту, конвейер не падает |
| 4.10 | ФНС отвечает с ошибкой два раза (ИНН `7731497609`) | retry с backoff, затем обычное решение |
| 4.11 | Ollama выключена | объяснение собирается по шаблону, `generatedByAi: false`, сценарий не прерывается |
